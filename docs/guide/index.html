On the line:

The closed loop for one artifact

Each artifact passes through a chain of roles, and the loop closes back on the Artifact Ledger. The model drafts; code checks, assigns IDs and stores.

Built on main Planned stand-in simple code does it today
Station 1 · builtSensorIntake and input guardrail. Checks, hashes and logs every artifact.
▶
Station 2 · plannedGovernorOrchestrator. Reads the artifact and sends work orders.
▶
Station 3 · partly builtRegistrarsSpecialist record keepers. Decision Registrar built, Risk Registrar planned. Code checks every draft.
▶
Station 4 · builtComparatorReconciliation. Finds related records with Embed and Rerank; Command judges new, update, reaffirmation or supersession.
▶
Back to · stand-inArtifact LedgerMarks the artifact processed and lists the records it produced.

Today: record-decision sends an accepted artifact to the Decision Registrar, then compares the checked draft with the Comparator, and a pipeline stand-in for the Governor updates the Ledger. The draft comes before the comparison on purpose: the Comparator only judges content already grounded in the artifact (ADR-0017). Around the line, the Operator (human in the loop) releases quarantined files; the Observer (quality control) and the Oracle (query interface) are planned.

    How to refresh this guide

    This is a living guide. A refresh never needs a special handoff: reread the same sources and update.

    1. Reread README.md, dev/STATUS.md, the latest file in dev/handoffs/ and any new ADRs in docs/decisions/.
    2. Update the diagrams in docs/diagrams/ first (solid when built on main, dashed or dotted when planned), then their copies in README.md and docs/architecture.md.
    3. Update this page: the stations, the status figures and lists, and the walkthrough if a new real run replaces it. Every "built" label must match main.
    4. Change the refresh date and commit in the footer.
